= Writing Assessments

== Installing the Infrastructure

1. `git pull`
2. `nvm use` (reads the pinned version from `.nvmrc`, currently `24.7.0`)
3. `npm install`
4. `npm update swyk-client`
5. You're ready to rock `./build-mdquiz` once you write an assessment!

== Writing an Assessment

Assessment questions are written directly in the lesson's own
`index.adoc`, right next to the content they're testing. The build system
collects them and writes each assessment's `quiz.json` -- the file
swyk-client reads -- into the lesson's `assessments/` folder in
`distribution/`. You never write a `quiz.json` by hand, and a lesson's
source has no `assessments/` folder. (Hand-written quizzes are no longer
supported: the build warns about any `assessments/` folder that its
`@checkpoint`s and `@assessment`s didn't write.)

Images a quiz uses go in the lesson's `images/` folder, like any other
image, with an entry in its `lesson-images.json`.

Design background and discussion: https://github.com/bootstrapworld/curriculum/issues/2888[issue #2888].
For examples, see `lessons/__Authoring/__sample-lesson-2`, and Data
Science lessons such as `box-plots` and `histograms-visualize`.

=== The four question directives

Each directive takes a fixed number of `{...}` groups, read in order --
there's no optional/variadic group, so "no value" is always an empty group
`{}`, never an omitted one.

`@short-answer{required-flag}{numeric-range}{prompt}{answer}`::
+
--
- First group: `{}` = required (the default). `{optional}` sets `validation.required` to `false`.
- Second group: `{}` = no numeric constraint. A `min..max` range sets `validation.numeric: true`; either side may be blank -- `{0..360}` sets both bounds, `{0..}` only `min`, `{..360}` only `max`, `{..}` numeric with no bounds at all.

  @short-answer{optional}{0..360}{How many degrees are in a right angle?}{90}
--

`@multiple-choice{order-mode}{prompt}{options}`::
+
--
The third group is an AsciiDoc checkbox list; mark the correct option(s) `[x]` in place (multiple `[x]`s produce a multi-select answer array).
`order-mode` is one of:

- `{}` or `{sorted}` -- alphabetically sorted (the default).
- `{shuffle}` or `{random}` -- randomized at render time.
- `{fixed}` -- options stay exactly where written; the correct answer's own position is preserved.

  @multiple-choice{sorted}{Which of these values is negative?}{
  - [ ] 12
  - [x] -4
  - [ ] 0
  - [ ] 7
  }
--

`@card-sort{ordered-flag}{prompt}{groups}`::
+
--
The third group is an AsciiDoc description list (`term::` followed by `- item` bullets) grouping cards into their correct piles. The term itself is discarded -- swyk-client never shows pile labels during sorting -- so just number the piles rather than inventing names for them. Card ids are auto-generated; you never write them by hand.
`{}` (default) or `{ordered}` sets `answer.ordered`.

  @card-sort{}{Match each histogram with the appropriate descriptive statement.}{
  1::
  - @image{images/histoA.png}
  - has a peak in the center
  2::
  - @image{images/histoC.png}
  - has an outlier on the right
  }
--

`@categorize{prompt}{groups}`::
+
--
Same term/item list shape as `@card-sort`, except here the term is a real, student-facing `leftColumn` label, not a discardable pile marker. Writing each category once with its matches listed underneath (rather than repeating the term once per match) leaves no room for a typo'd category name to silently create a second, mismatched entry. Both columns are shuffled for the student.

  @categorize{Distinguish between bar charts and histograms.}{
  Histogram::
  - HISTOGRAM
  - @image{images/hist-image.png}
  - uses quantitative data
  Bar Chart::
  - BAR CHART
  - uses categorical data
  }
--

Prompt/option/card/category text in all four directives is AsciiDoc, like
the rest of the lesson -- `+*bold*+`, `@image{path}` / `@image{path, size}`
and other directives included -- and is converted to HTML for `quiz.json`
at build time. (The exception is a short answer's answer key, which stays
plain text.) A literal `\n` in quiz text stands for a newline, so `\n\n`
starts a new paragraph.

An image's `description` in `lesson-images.json` is written for the
lesson, and in a quiz could give away the answer. So a quiz image doesn't
use it: it gets no tooltip, and its alt text comes from a separate
`quiz-description`, if the image has one -- describe the image so that a
student using a screen reader can answer the question, without answering
it for them. Without a `quiz-description`, the image has no alt text.

  "left-w-foot.png": {
    "description": "A hill-shaped histogram, with a clump of taller bars on the right side, and smaller bars trailing off to the left",
    "quiz-description": "A histogram",
    "source": "Created by the Bootstrap Team",
    "license": "Creative Commons 4.0 - NC - SA"
  }

=== Escape hatch: `@quiz-json{}`

For anything the four directives above don't cover -- the `Tracing`,
`Informational`, and `Pyret` question types, none of which have an inline
directive yet, or fields the directives don't set, like `Categorize`'s
`context` -- write the question's raw JSON directly. It's spliced into the
assessment's `questions` array as-is:

  @quiz-json{
  {
    "type": "Categorize",
    "id": "one-to-one-logic",
    "prompt": {
      "prompt": "One-to-One: *Computer Science Basics*\n\nMatch each term to its primary definition.",
      "leftColumn": ["Variable", "Function", "Boolean"],
      "rightColumn": ["A reusable block of code", "A container for storing data", "A data type with two possible values"]
    },
    "answer": {
      "Variable": ["A container for storing data"],
      "Function": ["A reusable block of code"],
      "Boolean": ["A data type with two possible values"]
    },
    "context": "In a one-to-one relationship, every item in the left column has exactly one unique partner in the right column."
  }
  }

Since it isn't converted, its text is Markdown, which swyk-client renders
(`+*italic*+`, `+**bold**+`, backquotes for code, `\n\n` for a new paragraph). A
Markdown image whose path is in the lesson's `images/` folder, like
`![](images/hist-image.png)`, is linked up the same way `@image` is, but
its alt text is whatever you write between the brackets. If the JSON
doesn't parse, the build warns and skips the question.

==== `quiz.json` question fields

Every question has a `type`, a `prompt` object with the `prompt` text, and
an `answer` object:

  { "type": "...", "prompt": { "prompt": "..." }, "answer": { "answer": "..." } }

What else each type takes:

- `MultipleChoice`: `prompt.distractors`, the wrong options. More than one `answer.answer` (an array) makes it multiple select. By default the options are randomized; `prompt.sortAnswers: true` sorts them, and `prompt.answerIndex` puts the answer at that position, with the distractors filling the other positions in order.
- `ShortAnswer`: an optional `prompt.validation` object -- `required` (defaults to `true`), `numeric`, and inclusive `min`/`max` bounds (only meaningful when `numeric` is `true`).
- `CardSort`: `prompt.cards`, an array of `{"id": ..., "content": ...}`; `answer.answer` lists the piles as arrays of card ids, and `answer.ordered` says whether order within a pile matters.
- `Categorize`: `prompt.leftColumn` and `prompt.rightColumn`; `answer` maps each `leftColumn` term to an array of its matching `rightColumn` term(s). An optional `id` gives the question a stable identifier, and an optional `context` adds explanatory text, shown with the correct answers.
- `Pyret`: embeds a live Pyret editor, pre-loaded with `prompt.program`. A `prompt.checkblock` (Pyret `check:`/`where:` code, run against whatever the student's editor holds when they submit) decides whether they passed. `answer.answer` is a plain string -- the sample solution shown to the student afterwards, not something graded against directly.
+
  @quiz-json{
  {
    "type": "Pyret",
    "prompt": {
      "prompt": "Write a function `double` that takes a number and returns twice its value.",
      "program": "fun double(n):\n  n * 2\nend",
      "checkblock": "check:\n  double(3) is 6\n  double(0) is 0\nend"
    },
    "answer": { "answer": "fun double(n):\n  n * 2\nend" }
  }
  }
- `Tracing` and `Informational`: swyk-client also ships these question types, undocumented here.

Any question can also have an `image`, the path of an image shown below its prompt.

=== Labeling a question: `@quiz-label`

To give a question a short label naming the skill or topic it assesses
(its `label` field, which results reports show in place of a bare question
number), put `@quiz-label{...}` just before it:

  @quiz-label{Useful bin size}
  @multiple-choice{sorted}{Which of the following displays would be most useful?}{
  ...
  }

The label is plain text, taken as written. It applies to the next question
directive -- any of the four above, or `@quiz-json{}` -- and labels are
optional. A `@quiz-label` that no question picks up (another `@quiz-label`,
`@checkpoint`, `@assessment`, or the end of the lesson comes first) gets a
warning.

=== Collecting inline questions into a `quiz.json`: `@checkpoint` and `@assessment`

Inline questions accumulate in a running list as the build walks through
the lesson. Two directives flush that list to disk:

`@checkpoint{title}`:: Collates every inline question seen since the last `@checkpoint` (or the start of the lesson) into its own `quiz.json`, titled "Show what you know: _title_ Checkpoint". A lesson can have as many checkpoints as it needs -- e.g. a short do-now/exit-ticket checkin partway through, and a fuller one later -- each independently titled and placed wherever it belongs, not tied to section boundaries.

`@assessment{title}`:: At most one per lesson. Concatenates *every* `@checkpoint`'s questions seen so far into one new, cumulative `quiz.json`, titled "Show what you know: _title_ (Cumulative)". Place it wherever the cumulative assessment belongs in the lesson -- it doesn't have to be the very last thing in the file (e.g. before a trailing "Data Exploration Project" section).

Each writes its quiz to `assessments/<slug>/`, where the slug is its
title in lowercase, with each run of characters other than letters and
digits replaced by a hyphen: `@checkpoint{Mean, Median, Modes Checkin}` writes
`assessments/mean-median-modes-checkin/`. So changing a title changes the
quiz's URL.

A lesson with only one quiz and no intermediate checkpoints
doesn't need an explicit `@checkpoint{}` before its
`@assessment{}` -- `@assessment{}` collects
any not-yet-checkpointed questions itself, in addition to every
``@checkpoint``'s questions so far.

=== Referring back to a quiz: `@old-assessment`

`@checkpoint` and `@assessment` link to the quiz they write, and add it to
the lesson's Assessments list. To mention the same quiz again later in the
lesson, use `@old-assessment{slug}`, which links up to the Assessments list
and shows the quiz's title -- or `@old-assessment{slug, text}` to show
`text` instead:

  ... the same questions as @old-assessment{mean-median-modes-checkin}.

The quiz must be written by a `@checkpoint` or `@assessment` earlier in the
lesson; otherwise the build warns.

=== Quizzes on a course page

A course's own page (`pathways/<course>/langs/en-us/index.adoc`) can hold
quizzes too. Its questions are written exactly as in a lesson, but are
usually collected with these two directives instead, which only a course
page can use:

`@course-checkpoint{title}{folder}`:: Like `@checkpoint`, but the quiz's title is exactly _title_ (no "Show what you know: ... Checkpoint" around it), and it goes in `assessments/_folder_/`, whatever its title -- so a course's quiz URLs stay put when a title changes.
`@course-assessment{title}{folder}`:: Likewise, for a cumulative quiz like `@assessment`'s.

_folder_ must be lowercase letters, digits and single hyphens. E.g.:

  @course-checkpoint{Data Science (Starting Benchmark)}{student-pre}

writes `distribution/en-us/courses/data-science/assessments/student-pre/quiz.json`,
titled "Data Science (Starting Benchmark)". A bad _folder_ is warned
about, and that quiz is skipped; its questions then go into the next one.
(`@checkpoint` and `@assessment` work on a course page too, as in a lesson.)

Differences from a lesson:

- The course page shows nothing where the directives are -- no link to
  the quiz, and no Assessments list. Link to the quiz some other way.
- Images a quiz uses go in the course's `images/` folder, with an entry
  in its `lesson-images.json`. The quiz gets an anonymized copy of each,
  leaving the original for the course page itself.
- A course may still have hand-written quizzes, in its source's
  `assessments/` folder (e.g. `student-pre/quiz.json`). An inline quiz
  written to the same folder overwrites that quiz. That's how to replace
  one with an inline version: write it inline with `@course-checkpoint`
  and that folder, and delete the hand-written one.

=== To build your quiz

1. Type `./build-mdquiz` in your terminal. It runs `make`, which writes the lesson's `quiz.json` files and warns about any question it had to skip, then builds each quiz's page.
2. Navigate to `distribution/en-us/lessons/name-of-lesson/assessments/slug-of-assessment/index.html`

You'll see a webpage pop up. It will say:

Quiz +
# of questions +
Start

When you click Start you will see the first question and you will need to enter a bogus answer (just choose A) in order to see the next question.

After you complete the quiz you will see a summary of the quiz.
