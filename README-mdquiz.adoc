= Writing Assessments

== Installing the Infrastructure

1. `git pull`
2. `nvm use 22.5`
3. `npm install`
4. `npm update mdquiz`
5. You're ready to rock `./build-mdquiz` once you write an assessment!

== Writing an Assessment

=== Setting up the assessments folder inside of the lesson

1. An `assessments` folder can be added to any folder at the same level as `authoring`, `images`, `pages`, etc.
2. The only thing we will see inside the `assessments` folder is subfolders, each one for a single assessment
3. The folder for each assessment included in the lesson should be named to make it clear what the assessment is about / for.
  - This folder must contain a file named `/* quiz.json`
  - If an assessment uses images, they must be stored in this folder.

You can look at `lessons/Data-Science/histograms-visualize/langs/en-us/assessments` for an example.

=== Writing the `/* quiz.json` file

1. It begins with a title that will end up being student-facing.

2. Question Types: We currently have four fully-functional question types: "MultipleChoice", "ShortAnswer", "CardSort", and "Categorize".

3. Every question must include

   {
    "type": "",
    "prompt": {
        "prompt": ""
        },
    "answer": {
        "answer": ""
        }
    }

4. Images can be added to any field inline.      \n\n ![](./salary-lr-plot.png)
+
If the autogenerated size with a max width of 640 pixels is unsatisfying, image sizes can be speficied using the following formatting
+
   ![](./pic/pic1_50.png =100x20)
+
Note: you must specify both a width and a height and doing so without paying attention to the original dimensions of the image will result in distortion!

5.  MultipleChoice questions also include "distractors". By default the order of the distractors and answer is randomized. If an `answerIndex` is given, the answer will be located at that index and the remaining indices will be populated by the distractors, _in order_. (In the example below, the choices will be ordered as "8, 12, <answer>, 18. Removing `"answerIndex": 2` will randomize all the choices.)

    "prompt": {
        "prompt": "A teacher surveys her students on how many hours of TV they watch per week. (See display for results.)\n\nHow many students did the teacher survey? \n\n ![](./salary-lr-plot.png)",
        "distractors": [
          "8",
          "12",
          "18"
        ],
        "answerIndex": 2
      },

6. MultipleChoice Questions can also be used as Multiple Select / Multi Check questions by declaring more than one answer. _Here's an example from the dot-plots formative assessment._
+
  "prompt": {"prompt": "Consider how the dot plot below would be different if the student named Sebastian weren’t in the class. Select each statement below that correctly describes a new dot plot of the class’ names without Sebastian. ![](./names2.png)",
                "distractors" : [
                  "There are no gaps in the display."
                ]
            },
             "answer" : {
              "answer" : [
                "Without the dot representing Sebastian, the range is 4 letters.",
                "The most common name length (6 letters) is also the longest name length.",
                "Variability decreases."
              ]
            }

7. ShortAnswer questions can optionally include a `validation` object to constrain what a student is allowed to submit: `required` (defaults to `true` if omitted), `numeric` (whether the answer must be a number), and inclusive `min`/`max` bounds (only meaningful when `numeric` is `true`). If no `validation` object is given at all, the question is assumed to be required with no other constraints — this matches every ShortAnswer question written before this feature existed, so nothing needs to change in older quizzes.

    {
        "type": "ShortAnswer",
        "prompt": {
            "prompt": "How many degrees are in a right angle?",
            "validation": { "numeric": true, "min": 0, "max": 360, "required": false }
        },
        "answer": { "answer": "90" }
    }

8. Categorize questions ask students to match each term in a `leftColumn` to one or more terms in a `rightColumn`. The `answer` maps each `leftColumn` term to an array of the matching `rightColumn` term(s) — usually just one, but you can list more than one if a left-hand term has multiple correct matches. Both columns are shuffled for the student, so their order in the JSON doesn't matter. An optional `id` gives the question a stable identifier, and an optional `context` adds explanatory text (shown after the student submits) — see the `Categorize` example below, whose `context` explains the "one-to-one" framing of that particular question.

9. \n\n is used to insert a new line in the middle of a string.

10. This is how to **bold** something.

Below is an example of what the complete json might look like. 

[options="nowrap"]
  {
    "title": "Emmanuel's Demo Quiz",
    "questions": [
      {
        "type": "MultipleChoice",
        "prompt": {
          "prompt": "What does it mean if a variable `x` is immutable?\n",
          "distractors": [
            "`x` is stored in the immutable region of memory.",
            "After being defined, `x` can be changed at most once.",
            "You cannot create a reference to `x`.![alt text](./react.svg 'react logo')"
          ]
        },
        "answer": {
            "answer": "`x` cannot be changed after being assigned to a value."
        }
      },
      {
          "type": "ShortAnswer",
          "prompt": {
              "prompt": "What is the keyword used after `let` to indicate that a variable can be mutated?      \n\n ![](./react.svg)"
          },
          "answer": {
              "answer": "mut"
          }
      },
      {
          "type": "CardSort",
          "prompt": {
              "prompt": "Sort these cards into colors and animals",
              "cards": [
                  {"id":"red",    "content": "red"},
                  {"id":"yellow", "content": "yellow"},
                  {"id":"blue",   "content": "blue![alt text](./react.svg 'react logo')"},
                  {"id":"green",  "content": "green![alt text](./bar-image.png)"},

                  {"id":"cat",    "content": "cat![alt text](./react.svg 'react logo')"},
                  {"id":"dog",    "content": "dog"},
                  {"id":"pig",    "content": "pig![alt text](./hist-image.png)"},
                  {"id":"wombat", "content": "wombat![alt text](./react.svg 'react logo')"}
              ]            },
          "answer": {
              "answer": [
                  ["red", "yellow", "blue", "green"],
                  ["cat", "dog", "pig", "wombat"]
              ],
              "ordered": false
          }
      },
      {
        "type": "Categorize",
        "id": "one-to-one-logic",
        "prompt": {
          "prompt": "One-to-One: *Computer Science Basics*\n\nMatch each term to its primary definition.",
          "leftColumn": ["Variable", "Function", "Boolean"],
          "rightColumn": ["A reusable block of code", "A container for storing data", "A data type with two possible values"]
        },
        "answer": {
          "Variable": ["A container for storing data"],
          "Function": ["A reusable block of code"],
          "Boolean": ["A data type with two possible values"]
        },
        "context": "In a one-to-one relationship, every item in the left column has exactly one unique partner in the right column."
      },
    ]
  }

=== Writing an assessment inline (alternative to hand-writing `quiz.json`)

Instead of hand-writing a `quiz.json`, you can write questions directly in
the lesson's own `index.adoc`, right next to the content they're testing.
The build system collects them and emits the same `quiz.json` mdquiz
already consumes -- the two approaches produce identical output, so pick
whichever is easier for a given assessment (or mix them: a hand-written
`quiz.json` and inline questions elsewhere in the same lesson are both
fine).

Design background and discussion: https://github.com/bootstrapworld/curriculum/issues/2888[issue #2888].

==== The four question directives

Each directive takes a fixed number of `{...}` groups, read in order --
there's no optional/variadic group, so "no value" is always an empty group
`{}`, never an omitted one.

`@shortAnswer{required-flag}{numeric-range}{prompt}{answer}`::
+
--
- First group: `{}` = required (the default). `{optional}` sets `validation.required` to `false`.
- Second group: `{}` = no numeric constraint. A `min..max` range sets `validation.numeric: true`; either side may be blank -- `{0..360}` sets both bounds, `{0..}` only `min`, `{..360}` only `max`, `{..}` numeric with no bounds at all.

  @shortAnswer{optional}{0..360}{How many degrees are in a right angle?}{90}
--

`@multipleChoice{order-mode}{prompt}{options}`::
+
--
The third group is an AsciiDoc checkbox list; mark the correct option(s) `[x]` in place (multiple `[x]`s produce a multi-select answer array).
`order-mode` is one of:

- `{}` or `{sorted}` -- alphabetically sorted (the default).
+
CAUTION: This default differs from hand-written `quiz.json`, where omitting `answerIndex`/`sortAnswers` means *randomized* order (see item 5 above). Inline questions default to `sorted` instead, per the design discussion on #2888.
- `{shuffle}` or `{random}` -- randomized at render time.
- `{fixed}` -- options stay exactly where written; the correct answer's own position is preserved.

  @multipleChoice{sorted}{Which of these values is negative?}{
  - [ ] 12
  - [x] -4
  - [ ] 0
  - [ ] 7
  }
--

`@cardSort{ordered-flag}{prompt}{groups}`::
+
--
The third group is an AsciiDoc description list (`term::` followed by `- item` bullets) grouping cards into their correct piles. The term itself is discarded -- mdquiz never shows pile labels during sorting -- so just number the piles rather than inventing names for them. Card ids are auto-generated; you never write them by hand.
`{}` (default) or `{ordered}` sets `answer.ordered`.

  @cardSort{}{Match each histogram with the appropriate descriptive statement.}{
  1::
  - @image{images/histoA.png}
  - has a peak in the center
  2::
  - @image{images/histoC.png}
  - has an outlier on the right
  }
--

`@categorize{prompt}{groups}`::
+
--
Same term/item list shape as `@cardSort`, except here the term is a real, student-facing `leftColumn` label, not a discardable pile marker. Writing each category once with its matches listed underneath (rather than repeating the term once per match) leaves no room for a typo'd category name to silently create a second, mismatched entry.

  @categorize{Distinguish between bar charts and histograms.}{
  Histogram::
  - HISTOGRAM
  - @image{images/hist-image.png}
  - uses quantitative data
  Bar Chart::
  - BAR CHART
  - uses categorical data
  }
--

All four directives accept `@image{path}` / `@image{path, size}` inline in
prompt/option/card/category text (converted to the same Markdown image
syntax used in hand-written `quiz.json`), and AsciiDoc `*bold*` (converted
to Markdown `**bold**`). Nothing else gets expanded -- for anything more
elaborate a prompt needs, fall back to a hand-written `quiz.json`, or the
`@quizJSON{}` escape hatch below.

==== Escape hatch: `@quizJSON{}`

For anything the four directives above don't cover -- today, that's the
`Tracing`, `Informational`, and `Pyret` question types, none of which have
an inline directive yet -- write the question's raw JSON directly and it's
spliced into the assessment's `questions` array as-is, same as a
hand-written `quiz.json` entry:

  @quizJSON{
    { "type": "Tracing", "prompt": { ... }, "answer": { ... } }
  }

==== Collecting inline questions into a `quiz.json`: `@checkpoint` and `@cumulativeAssessment`

Inline questions accumulate in a running list as the build walks through
the lesson. Two directives flush that list to disk:

`@checkpoint{title}`:: Collates every inline question seen since the last `@checkpoint` (or the start of the lesson) into its own `quiz.json`, titled `title`. A lesson can have as many checkpoints as it needs -- e.g. a short do-now/exit-ticket checkin partway through, and a fuller one later -- each independently titled and placed wherever it belongs, not tied to section boundaries.

`@cumulativeAssessment{title}`:: At most one per lesson. Concatenates *every* `@checkpoint`'s questions seen so far into one new, cumulative `quiz.json`, titled `title`. Place it wherever the cumulative assessment belongs in the lesson -- it doesn't have to be the very last thing in the file (e.g. before a trailing "Data Exploration Project" section).
+
NOTE: Not the same directive as the existing `@assessment{label}`, which links to an already-existing `assessments/<label>/` folder elsewhere in a lesson -- see "Setting up the assessments folder" above. Once `@cumulativeAssessment{title}` has written its `quiz.json`, `@assessment{}` can link to it the same way it links to any hand-written one.

A lesson with only one quiz and no intermediate checkpoints
doesn't need an explicit `@checkpoint{}` before its
`@cumulativeAssessment{}` -- `@cumulativeAssessment{}` collects
any not-yet-checkpointed questions itself, in addition to every
``@checkpoint``'s questions so far.

=== To build your quiz

1. Type `./build-mdquiz` in your terminal.
  - If you get an error like the following one `The quiz.json file inside distribution/en-us/lessons/measures-of-center/assessments/mean-median-modes-checkin is not valid JSON!`
    ** Open a browser window and type "json validator" or navigate directly to https://jsonlint.com/
    ** Select All and copy the contents of your `/* quiz.json` file. 
    ** Paste the full contents of the document into the json validator. 
    ** Click "validate" and it will identify the first issue with the file. Identify and repeat validation until you get a "JSON is valid!" message.
    ** Update the file in sublime and rerun `./build-mdquiz`.
2. Navigate to `distribution/lessons/name-of-lesson/assessments/name-of-assessment/index.html`

You'll see a webpage pop up. It will say:

Quiz +
# of questions +
Start

When you click Start you will see the first question and you will need to enter a bogus answer (just choose A) in order to see the next question.

After you complete the quiz you will see a summary of the quiz.
